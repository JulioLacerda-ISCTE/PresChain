Por que é isto seguro?
🔐 Chave Privada Única
Cada deputado tem uma chave criptográfica pessoal, intransferível. Ninguém pode assinar em seu nome — ao contrário de uma password que pode ser partilhada (caso Silvano, 2018).
🌐 Imutabilidade Blockchain
Uma vez gravado, o registo não pode ser alterado por nenhum administrador, técnico ou entidade política. Qualquer cidadão pode auditar.
⏱️ Timestamp Verificável
O timestamp é gerado pelo próprio bloco Ethereum — não pelo servidor da AR. É matematicamente impossível falsificar o momento do registo.
🛡️ Proteção Anti-Replay
Cada sessão tem um ID único (hash). A mesma assinatura não pode ser reutilizada noutra sessão, prevenindo ataques de replay.
Auditoria Blockchain — Registos Imutáveis
Todos os registos de presença estão gravados on-chain. Qualquer cidadão, jornalista ou entidade pode verificar estas transações no explorador de blocos da Ethereum, a qualquer momento.

Smart Contract — PresençaChain.sol
O contrato inteligente em Solidity que corre na Ethereum. Define as regras de negócio imutáveis: quem pode registar, como se valida, e o que fica gravado para sempre.
Funções Principais
registarPresenca(sessaoId)
Grava a presença do deputado. Apenas o próprio pode chamar esta função (onlyDeputado). Emite evento imutável.
verificarPresenca(dep, sessaoId)
Função pública de consulta. Qualquer pessoa pode verificar se um deputado esteve presente numa sessão.
criarSessao(id, timestamp)
Apenas a Mesa da AR pode abrir novas sessões. Cria o ID único que previne ataques de replay.
PresencaChain.sol · Solidity 0.8.x
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract PresencaChain {

  struct Registo {
    address deputadoDID;
    uint256 timestamp;
    bytes32 sessaoHash;
    bool    confirmado;
  }

  struct Sessao {
    bytes32 id;
    uint256 inicio;
    bool    ativa;
  }

  mapping(address => bool)
    public deputados;

  mapping(bytes32 => Sessao)
    public sessoes;

  mapping(address =>
    mapping(bytes32 => Registo))
    public registos;

  event PresencaRegistada(
    address indexed dep,
    bytes32 indexed sessaoId,
    uint256 timestamp
  );

  // Só o próprio dep. pode registar
  modifier onlyDeputado() {
    require(deputados[msg.sender],
      "Nao autorizado");
    _;
  }

  function registarPresenca(
    bytes32 sessaoId
  ) external onlyDeputado {
    require(sessoes[sessaoId].ativa,
      "Sessao inativa");
    require(
      !registos[msg.sender][sessaoId]
        .confirmado,
      "Ja registado"
    );

    registos[msg.sender][sessaoId] =
      Registo({
        deputadoDID: msg.sender,
        timestamp: block.timestamp,
        sessaoHash: sessaoId,
        confirmado: true
      });

    emit PresencaRegistada(
      msg.sender,
      sessaoId,
      block.timestamp
    );
  }
}

Sistema Atual vs. PresençaChain
Aspeto Sistema Atual (AR) PresençaChain (Blockchain)
Autenticação ⚠️ Login + password partilhável (caso Silvano) ✅ Chave privada criptográfica intransferível (DID)
Armazenamento ⚠️ Base de dados centralizada (alterável) ✅ Blockchain imutável — ninguém pode alterar
Transparência ⚠️ Acesso restrito ao portal da AR ✅ Qualquer cidadão verifica no explorador de blocos
Timestamp ⚠️ Gerado pelo servidor da AR ✅ Gerado pela rede Ethereum (impossível falsificar)
Auditoria ⚠️ Apenas serviços internos da AR ✅ Pública, permanente, resistente a censura
Replay Attack ⚠️ Vulnerável (mesma password) ✅ Cada sessão tem hash único — reutilização impossível
